# Explicit task Mach restriction

New materialization may request `task_mach_boundary=True` together with the
observer network contract. The frozen binding records the exact two operations
and three execution roles. Startup validation reconstructs the profiles and
rejects omitted rules even if the broader profile has a new file hash.

The app-server and both Claude lanes deny `mach-lookup` and `appleevent-send`.
Their descendants inherit this policy. The remote TUI and external controller
retain their existing profiles and can perform the original authorized UI and
research operations. Existing tasks and default materialization are unchanged.

Real temporary Darwin probes verify refused Mach lookup and kernel AppleEvent
permission checks in direct and descendant processes. Separate local checks
found the original official Codex 0.164.0 and Claude 2.1.303 version commands
working under this restriction. Those checks do not prove model calls or
automatic hooks. Exact model-port, observer and callback connectivity remain
separate tests.

This policy does not revoke already inherited Mach rights or establish native
helper FD behavior, gateway semantics or complete broker isolation. Full TASK
adoption and launch remain unavailable until the remaining runtime evidence is
implemented and verified. No live profiles are changed by these tests.
